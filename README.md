# Dashboard ติดตามงานเปลี่ยนทดแทน

Dashboard ภาษาไทยสำหรับนำเข้า SAP CSV/XLSX รายสัปดาห์ แยกงบ 2xxx / 3xxx, โครงการ HB (2567–2568), JA (2568–2569), M4 (2569), กฟฟ. และสถานะ พร้อมเปรียบเทียบ WBS ระหว่างวันที่และส่งออก CSV

## เริ่มใช้งาน

ใช้ Python 3.12 ขึ้นไป:

```sh
cd /workspace/DashboardFollowUp2xxx-3xxx
python3 -m pip install -r requirements.txt
python3 setup.py
python3 app.py --port 8000
```

เปิดเว็บผ่านช่องทางเข้าถึงพอร์ตของเครื่องที่รันระบบ เลือก “นำเข้าข้อมูลประจำสัปดาห์” เลือกวันที่ข้อมูลจริงและไฟล์ SAP ดิบ CSV/XLSX ระบบรักษาข้อมูลวันที่เดิมและปฏิเสธการนำเข้าวันที่ซ้ำ

## วิธีคำนวณ

- งบปัจจุบัน = คอลัมน์ `งบประมาณปัจจุบัน` ของ SAP
- เบิกจริง = `รวม Act.ทั้งหมดที่ควบคุม งปม.` ของ SAP ไม่บวกคอลัมน์ Act ย่อยซ้ำ
- คงเหลือ = `งบประมาณคงเหลือ` ของ SAP อาจไม่เท่ากับงบปัจจุบันลบเบิกจริง เพราะรายการผูกพัน/การจัดสรร
- เงินเก็บเป็นจำนวนเต็มหน่วยสตางค์
- ใช้เฉพาะ Lv 5 และ WBS กลุ่ม HB/JA/M4 ที่ลงท้าย 2xxx/3xxx ไม่รวมแถว Lv 3/4
- F4 หรือ SAP CLSD = ปิดงานแล้ว รหัสอื่นแสดงตามจริง ยังไม่มีการกำหนดลำดับความคืบหน้า
- WBS ซ้ำที่ข้อมูล SAP เหมือนกันตัดเหลือหนึ่งรายการ ถ้าขัดแย้งปฏิเสธไฟล์ทั้งหมด
- จับคู่ด้วย WBS และเปรียบเทียบเฉพาะงบที่มีในทั้งสองไฟล์ งานไม่พบในไฟล์ใหม่ไม่ถือว่าปิดแล้ว
- ไฟล์มีแค่งบ 2xxx จะไม่สร้างข้อมูลสมมติสำหรับ 3xxx ต้องเลือก snapshot ที่มีงบดังกล่าว
- ค่าเริ่มต้นติดตามเฉพาะงานตามชีตตัวอย่าง สามารถเลือก “งานย่อย SAP ทั้งหมด” เพื่อดูงานนอกตัวอย่าง กฟฟ. ของงานเหล่านั้นยังไม่ระบุ
- ตัวกรองค้นหา/สถานะ/เฉพาะงานเปลี่ยนใช้กับตารางและ CSV ส่วนตัวกรองด้านบนใช้กับยอดรวมและกราฟ

## ข้อมูลตั้งต้นและการเก็บประวัติ

ข้อมูลจริงที่ผู้ใช้แนบ ณ 5 ตุลาคม 2569 อยู่ใน `data/seed.json` พร้อมข้อมูล กฟฟ. จากชีตตัวอย่างใน `data/reference.json` ทั้งสองไฟล์มีข้อมูลงานจริงขององค์กร ควรใช้ใน repository ที่มีสิทธิ์เข้าถึงเหมาะสม

ตามชีตตัวอย่างจับคู่ได้ 334 งาน: งบ 2xxx 318 งาน งบ 3xxx 16 งาน งบรวม 109,518,090.58 บาท เบิกจริง 78,828,008.90 บาท

SQLite เก็บใน `data/dashboard.sqlite` (ไม่เข้า Git) `setup.py` คืนข้อมูลตั้งต้นเฉพาะเมื่อฐานว่าง ไม่เขียนทับประวัติ ควรสำรองฐานข้อมูลก่อนย้ายเครื่อง ไม่สมมติว่าประวัติอัปโหลดใหม่จะอยู่ใน snapshot ของ environment ที่เผยแพร่ก่อนหน้า

## ตรวจสอบ

```sh
python3 -m unittest -v
node --check static/app.js
```

สำหรับเว็บไซต์ออนไลน์ มี HTTP Basic Authentication ผ่าน APP_USERNAME / APP_PASSWORD และบังคับใช้ด้วย REQUIRE_AUTH=1 (ค่าเริ่มต้นใน Docker) ต้องเปิดผ่าน HTTPS และใช้ disk ถาวร ยังไม่มีสิทธิ์แยกรายผู้ใช้ ดู [DEPLOY.md](DEPLOY.md) สำหรับ Render/VPS และการสำรองข้อมูล
